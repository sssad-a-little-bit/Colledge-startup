# Отчёт об испытаниях

Дата: 7 ноября 2026. Это результаты локальной синтетической демонстрации, не подтверждение готовности к промышленной эксплуатации. «КИТ Campus» — рабочее название; сведения о колледже не выдумывались.

## Что реализовано

Реальная PostgreSQL, Prisma и две миграции; NextAuth Credentials, bcrypt и проверка действующего пользователя на каждом запросе; серверные права на назначения, группы, собственные оценки и экспорт. Кабинеты трёх ролей, административные справочники, архивирование/деактивация, назначения, занятия, контрольные, настраиваемые шкалы, журнал с версией и неизменяемой историей, новости с аудиториями, атомарные уведомления и аудит, CSV с предпросмотром и идемпотентностью. Персональные HTTP-ответы — private/no-store.

Расписание хранится только развёрнутыми занятиями по датам. Недельная серия генерируется CLI в CSV с диапазоном и исключениями; перед записью используется обычный административный предпросмотр/импорт. Это не второй механизм хранения шаблонов. Связанная контрольная при замене аудитории/преподавателя синхронизируется транзакционно; перенос времени связанной пары требует сначала явно изменить/отвязать контрольную, иначе сервер отклоняет перенос с объяснением.

## Среда фактических проверок

- Linux x86_64, Node.js 24.22.1, npm 11.9.0; Docker rootless, PostgreSQL 17.7-bookworm.
- Среда предоставляет 3 CPU и около 9,7 GiB RAM; диск overlay около 7,9 GiB. Генератор и сервер находятся в одной среде. Лимиты контейнера PostgreSQL через cgroups не заданы.
- Next.js 15.5.29: `npm run build`, затем **`npm start` / `next start`**, а не dev-сервер. БД `campus_demo`, только синтетические данные; localhost без внешнего reverse proxy/TLS.
- Браузер Chromium из Playwright 1.56.1: 390×844, 768×1024 и 1440×1000. Dockerfile с Node 22.21.1 подготовлен; его сборка в этой среде **не проверена**.
- Промежуточный браузерный прогон обнаружил отсутствие выбора шкалы при поздней загрузке справочника; форма исправлена, итоговые 21 сценарий прошли. Проверяющий CLI после намеренного рестарта БД теперь явно переподключает собственное соединение; это не повтор записи. Первоначально диск заполнился во время сборки; удалён только временный npm-кеш, затем итоговая сборка успешно выполнена. Прерванные/неуспешные первые попытки не засчитываются как пройденные.

## Нагрузка

Проверено **100 одновременно активных пользователей с отдельными учётными записями и cookie-сессиями**. Production `next start`, 10 с разгона + 60 с устойчивой фазы, паузы между действиями 750–1250 мс. Вход каждого пользователя выполнен отдельно перед измерением и не включён в задержки. Профиль: 70% личное расписание, 25% адресные новости, 5% разрешённые записи собственного профиля. Это динамические запросы к БД с проверкой прав, а не только статические страницы.

В БД при запуске: 250 пользователей, 110 занятий, 9 контрольных, 96 оценок, 13 новостей. 100 аккаунтов текущего прогона после теста деактивированы; БД также содержит деактивированные аккаунты предыдущего испытания.

Ограничения: короткий локальный тест на небольшой БД, без WAN/TLS и reverse proxy, сервер и генератор делят ресурсы; запись профиля не моделирует нагрузку массового выставления оценок. Конкурентное исправление оценок проверялось отдельно интеграционно. Это выполненный уровень данной демонстрации, а не обещание доступности или скорости для колледжа. Исходная цель100 активных пользователей — предложенная гипотеза.

## Требует проверки перед пилотом

- Полный ручной аудит доступности, экранный диктор, Safari/Firefox, контраст всех состояний; автоматический проход клавиатурой покрывает основные элементы, но не заменяет аудит WCAG.
- Docker build и запуск целого приложения в контейнере, реальная CI-система и инфраструктура размещения; CI-файл подготовлен, удалённый pipeline не запускался.
- TLS/reverse proxy, раздельные роли владельца миграций и runtime, инфраструктурные ограничения, обновление зависимостей, независимый pentest, процесс реагирования и хранение резервных копий вне сервера.
- Длительная нагрузка, WAN/мобильные сети, массовые импорты и одновременное редактирование множества журналов на реальном объёме данных. Локальные результаты на маленькой БД нельзя переносить на весь колледж.
- Полное отключение питания/диска, многосерверный failover, длительная недоступность. Никаких гарантий 100% доступности нет.

## Явные ограничения реализации

В уже открытом кабинете данные обновляются при переходе, перезагрузке или кнопке обновления; автоматическая фоновая доставка изменений не реализована. Нет файловых вложений/загрузки аватаров и их резервирования, внешнего журнала/SSO, почты/Telegram/push, казахского интерфейса, графического редактора повторяющихся серий. Среднее по оценкам — справочная арифметика по выбранной странице и одной шкале, не итоговая аттестация. Список дел на учебный день формируется из событий; пользовательский менеджер задач не заявлен. Для пилота потребуются официальное название и разрешённая символика, регламент и шкалы, список уполномоченных и назначения, правила видимости и хранения контактов, основание обработки данных, инфраструктура, ответственные за поддержку, срок и критерии конкурса.

## Воспроизведение

Все проверки с записью выполняются **только в отдельной demo/test БД**. Не подставляйте production DSN. Запустите приложение по README, экспортируйте локальные переменные окружения; не выводите их в логи.

```bash
npm run lint
npm run typecheck
npm run build
npm start
# Отдельный терминал с TEST_DATABASE_URL и NEXTAUTH_SECRET:
npm run test:integration
npm test
npx playwright install chromium
npm run test:e2e
# Отдельно, без параллельных E2E/build:
LOAD_TEST=1 node --env-file=.env --import tsx scripts/load-test.ts
# Только для изолированного kit-campus-db/campus_demo:
RESILIENCE_TEST=1 node --env-file=.env --import tsx scripts/resilience-test.ts
# Не печатать локальные секреты:
AUTH_LIVE_TEST=1 TEST_DATABASE_URL="$DATABASE_URL" node tests/auth-live.mjs
DEMO_SEED=1 node --env-file=.env --import tsx prisma/verify-integrity.ts
BACKUP_CONTAINER=kit-campus-db BACKUP_DB=campus_demo bash scripts/backup.sh
BACKUP_CONTAINER=kit-campus-db BACKUP_DB=campus_demo bash scripts/restore-check.sh backups/FILE.dump
```

Соответствие экранов, действий и таблиц: [docs/ACCEPTANCE.md](docs/ACCEPTANCE.md). Цели пилота и восстановления указаны отдельно как гипотезы в [docs/PILOT.md](docs/PILOT.md).
