# КИТ Campus — учебный демонстрационный портал

**Демонстрационный проект. Данные вымышлены.** «КИТ Campus» — рабочее название конкурсного проекта IT STARTUP, а не утверждённый бренд или официальный сайт колледжа. Подтверждённый контекст: колледж КИТ, Павлодар, Казахстан. Полное официальное название, правила обучения и оценивания не предоставлены. Проект не объявляется готовым к промышленной эксплуатации.

Портал объединяет расписание, контрольные, оценки, новости и внутренние уведомления. Основной сценарий: администратор публикует занятие, преподаватель планирует контрольную и выставляет оценку, студент видит собственные данные и изменения. Данные хранятся в PostgreSQL; смена роли требует настоящего входа в другую учётную запись.

## Технологии и границы

- Next.js 15.5.29, TypeScript, React 19.1.10, Tailwind CSS 4.1.17.
- PostgreSQL 17.7, Prisma 6.19.0 с SQL-миграцией и ограничениями целостности в БД.
- NextAuth.js 4.24.15: локальный вход по паролю, bcrypt, cookie-сессия; активность пользователя и действующие назначения проверяются сервером заново.
- Vitest и Playwright. Закреплённые версии и `package-lock.json` обеспечивают воспроизводимость npm-установки.

Это модульный монолит: `app/` — страницы и HTTP-граница, `components/` — интерфейс, `lib/` — серверные правила, `prisma/` — схема, миграция и явный seed. Платные API, CDN, LLM, почта и внешние системы колледжа не нужны для установленной демонстрации. Интернет нужен для первой установки npm-пакетов, образа PostgreSQL и браузера для E2E; затем приложение работает с локальной БД.

## Быстрый локальный запуск

Требуются Node.js 22.21+ или 24, npm, Docker и Docker Compose. Команды ниже предназначены для **отдельной демонстрационной БД**, без реальных сведений.

```bash
cp .env.example .env
```

Отредактируйте `.env` локально. Задайте случайный `POSTGRES_PASSWORD`, тот же пароль в `DATABASE_URL`, `NEXTAUTH_URL=http://localhost:3000`, случайный `NEXTAUTH_SECRET` длиной не менее 32 символов. Не отправляйте секреты в репозиторий или чат. Пример получения случайного значения: `openssl rand -hex 32`. Если пароль содержит специальные символы, закодируйте его для URL. Сохраняйте кавычки вокруг `DATABASE_URL`, поскольку URL содержит `&`.

```bash
npm ci
set -a
. ./.env
set +a
export COMPOSE_PROJECT_NAME=kit-demo
docker compose up -d db
npm run db:migrate
DEMO_SEED=1 npm run db:seed
npm run build
npm start
```

Откройте <http://localhost:3000>. Для разработки вместо двух последних команд: `npm run dev`. В случае занятого порта PostgreSQL измените опубликованный порт в `compose.yaml` и `DATABASE_URL` согласованно.

Seed явно разрешается `DEMO_SEED=1`, запрещён при `NODE_ENV=production`, не запускается при старте сервера и не очищает таблицы. Повторный запуск добавляет отсутствующие демонстрационные записи, сохраняя существующие записи и пароли. Не направляйте seed на БД с реальными данными. Для полностью чистой демонстрации используйте новый Compose-проект и новый порт, а не удаление чужого тома.

## Вход

После seed локальный файл `.demo-credentials` содержит сгенерированные данные входа. Файл исключён из Git и создаётся с правами `0600`. Не публикуйте его. Основные логины:

| Роль | Логин |
| --- | --- |
| Администратор | `admin@demo.kit.local` |
| Преподаватель | `teacher@demo.kit.local` |
| Студент | `student@demo.kit.local` |

Пароль берётся **из локального файла**, фиксированного production-пароля нет. Самостоятельной регистрации с выбором роли нет. Основные адреса: `/`, `/news`, `/login`, `/campus`, `/campus/schedule`, `/campus/assessments`, `/campus/grades`, `/campus/notifications`, `/campus/profile`, `/campus/admin`.

## Существенные предположения

1. Нейтральные цвета и название проекта не являются айдентикой колледжа. Все имена, программы, группы, новости, аудитории и учебные события в seed синтетические.
2. Демонстрационная шкала — целые значения 0–100. Пропуск, отсутствие оценки и ноль различаются. Среднее, если показано, — арифметическое только по числовым записям и не официальная итоговая оценка.
3. Выбрана **одна модель расписания: отдельные занятия по конкретным датам**. Seed разворачивает несколько недель. Изменение конкретного занятия является исключением по дате; параллельной системы шаблонов нет. Для недельной серии с диапазоном и исключениями есть генератор CSV: `node --import tsx scripts/generate-weekly.ts docs/weekly-example.json /tmp/week.csv`; затем административный предпросмотр и атомарный импорт. Генератор не пишет в БД. Графический редактор повторяющихся серий — дальнейшая работа.
4. Временные моменты хранятся в `timestamptz`; учебное время отображается через IANA `Asia/Almaty`. CSV принимает ISO 8601 с явным часовым поясом. Нельзя считать локальное время UTC или вручную закреплять постоянное смещение.
5. Порог числа контрольных в день — демонстрационная настройка, по умолчанию 2, а не учебный регламент.
6. Локальная идентичность по email и паролю достаточна для демонстрации. Интеграция с существующим журналом, замена журнала, SSO и доставка внешних сообщений не предполагаются.
7. Вложения и загрузка фотографий не входят в текущий контур: отсутствующий механизм загрузки не должен заменяться открытым файловым каталогом.

## Целостность и права

Сервер ограничивает данные текущим пользователем, группой и действующим назначением преподавателя. Гость видит опубликованные публичные новости. Администратор управляет справочниками и публикациями; изменение оценок требует отдельного полномочия и причины. Аккаунты и назначения деактивируются, связанные учебные записи не удаляются каскадно.

Пересечения интервалов занятий проверяются ограничениями PostgreSQL по преподавателю, группе и аудитории, включая конкурентные записи. Исправления используют версии записей, история оценок и аудит защищены от обычного изменения и удаления. Учебное изменение и внутренние уведомления сохраняются транзакционно. Защита не распространяется на владельца БД, способного менять схему: production-роль приложения и права владельца миграций должны быть разделены.

CSV: шаблон и предварительная проверка в административном разделе; политика дублей — отклонение, импорт атомарный. Экспорт выполняет серверную проверку доступа и экранирует потенциальные формулы. Точный реализованный и проверенный объём указан в [TEST_REPORT.md](TEST_REPORT.md) и [матрице приёмки](docs/ACCEPTANCE.md).

## Проверки

Используйте отдельную тестовую БД. Проверки с изменением данных нельзя направлять на production.

```bash
npm run lint
npm run typecheck
npm test
npm run build
npm start
# В отдельном терминале, с окружением тестовой БД:
npm run test:e2e
```

Установка браузера для первой проверки: `npx playwright install chromium` (системные библиотеки могут требовать отдельной установки). Условия integration-, E2E- и нагрузочного запуска, фактически выполненные команды и результаты приведены в [TEST_REPORT.md](TEST_REPORT.md). Наличие теста в исходниках не означает его успешное выполнение.
