# Зависимости и совместимость

Версии прямых зависимостей закреплены без `^`/`~` в `package.json`; транзитивные зависимости и integrity зафиксированы в `package-lock.json` формата 3. Воспроизводимая установка — `npm ci`, изменение версий требует повторного запуска проверок.

В `overrides` закреплены транзитивные `postcss` **8.5.32**, `effect` **3.22.4** и `deepmerge-ts` **8.0.2**. После обновления пакетов и overrides необходимы `npm ci`, проверка типов, тесты и production build: в том числе потому, что принудительная версия может выходить за исходный диапазон транзитивного потребителя. Обновление lockfile само по себе не доказывает совместимость или устранение всех уязвимостей. Фактический результат аудита зависимостей фиксируется отдельно в `TEST_REPORT.md`; в момент этого обновления документа итог повторного аудита ещё не получен.

В `Dockerfile` выбрана Node.js **22.21.1** на Debian Bookworm с OpenSSL: эта версия соответствует явно описанной ветке Node.js в документации Prisma 6. Рабочая среда разработки использует Node.js **24.22.1**; её принимает `engines` закреплённых пакетов. Успешный запуск отдельных проверок в этой среде не означает отдельную сертификацию Prisma 6 для Node.js 24. Текущая общая [страница системных требований Prisma](https://www.prisma.io/docs/orm/reference/system-requirements) описывает также более новую ветку ORM; её требования не подменяют версионное руководство Prisma 6.

NextAuth и Prisma выполняются в Node.js runtime, не в Edge. [Инициализация NextAuth](https://next-auth.js.org/configuration/initialization) поддерживает App Router Route Handler с экспортами `GET` и `POST`; так устроен маршрут проекта. Пользовательские роли не сохраняются как источник прав в JWT: активность аккаунта и назначения перечитываются из БД при обращении.

Проверка peer-диапазонов выполнена чтением `node_modules/<package>/package.json`; установка закреплена lockfile. Официальные страницы были получены по HTTPS с включённой проверкой сертификатов. Это проверка заявленных требований и конфигурации, а не гарантия отсутствия уязвимостей. Перед пилотом нужны повторный аудит актуальности версий, проверка advisory и полная проверка контейнера в целевой инфраструктуре.
