# Общая ссылка через GitHub и Vercel

GitHub хранит исходный код и запускает обновления Vercel после изменений основной ветки. Vercel исполняет Next.js, а Neon хранит PostgreSQL. Постоянный адрес портала: [colledge-startup.vercel.app](https://colledge-startup.vercel.app). [GitHub Pages](https://sssad-a-little-bit.github.io/Colledge-startup/) автоматически перенаправляет на этот адрес. Для работы общей ссылки локальный сервер на ПК не требуется.

## Подключение

1. В Vercel импортируйте репозиторий `sssad-a-little-bit/Colledge-startup`, выберите Next.js и корневую папку репозитория. Используйте Node.js **24.x** в настройках сборки.
2. В Storage / Marketplace подключите Neon Postgres **17** в том же или ближайшем регионе. База должна поддерживать расширение `btree_gist`, используемое миграциями.
3. Сохраните перечисленные ниже переменные в настройках окружения **Production** Vercel. Значения не добавляются в GitHub.
4. Запустите Production deployment. Репозиторий уже содержит `vercel.json` с отдельной командой облачной сборки.
5. Для общего доступа проверьте **Deployment Protection** у production-адреса: посетителю не должен требоваться аккаунт Vercel. Вход студента или преподавателя внутри самого портала остаётся обязательным для личного кабинета.

Эти файлы сами не создают аккаунты, хостинг или платные ресурсы.

## Переменные окружения

| Переменная        | Значение                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`    | Пул подключений выбранной облачной БД с TLS; при необходимости добавьте `connection_limit=8&pool_timeout=10&connect_timeout=5`. |
| `DIRECT_URL`      | Необязательно: прямое подключение к той же БД для миграций. Если не задано, миграции используют `DATABASE_URL`.                 |
| `NEXTAUTH_URL`    | Точный HTTPS-адрес production-портала из Domains, без пути раздела.                                                             |
| `NEXTAUTH_SECRET` | Отдельный случайный облачный секрет длиной не менее 32 символов.                                                                |

`VERCEL_ENV` задаёт сама платформа. Для применения миграций оно должно быть равно `production`; включите доступ к системным переменным в настройках Vercel. Не устанавливайте эту переменную вручную в Preview.

## Сборка и данные

`scripts/vercel-build.mjs` последовательно генерирует Prisma Client, проверяет конфигурацию Production, применяет сохранённые миграции только для Production и собирает Next.js. `DIRECT_URL` заменяет `DATABASE_URL` только в процессе миграций; приложение продолжает использовать пул подключений. `npm run build` для локальной работы не меняется.

Сборка и запуск **не создают учеников, оценки или аккаунты автоматически**. Для первоначального наполнения можно один раз перенести согласованную копию подготовленных локальных данных в отдельную пустую облачную БД через `pg_dump` / `pg_restore`, сверив роли владельцев и права. Перед таким переносом нужна резервная копия выбранной БД. Локальный `scripts/prepare-campus.ts` намеренно ограничен локальной базой и для облачного переноса не запускается. Пароли аккаунтов, строки подключения и файл учётных данных не публикуются в репозитории.

Preview-сборки не изменяют схему Production. Для работающего предпросмотра задайте отдельную ветку БД с применённой схемой и собственные `NEXTAUTH_URL` и `NEXTAUTH_SECRET` в окружении Preview.

## Проверка ссылки

На production-адресе `/api/health/live` и `/api/health/ready` должны возвращать HTTP 200. Проверьте вход, список групп, оценки и кружки, затем откройте адрес в приватном окне без аккаунта Vercel. После успешной публикации этот адрес можно разместить в описании GitHub-репозитория и на GitHub Pages.
